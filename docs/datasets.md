# External ground-truth datasets

This document describes the opt-in workflow for downloading, positioning,
and manifesting external LaTeX corpora used by `pdf2md` for backend
evaluation and consensus calibration.

External datasets are **not vendored**: they must be downloaded by the
user. They are kept strictly separate from the canonical synthetic
fixtures under `groundtruth/corpus/latex/`.

---

## Where each kind of dataset lives

| Directory | Source | Status | Used by |
|---|---|---|---|
| `groundtruth/corpus/latex/` | Synthetic fixtures generated by `generate_latex_docling_groundtruth.py` | Canonical, committed in-tree | All Plans 8–17 acceptance gates |
| `groundtruth/external/` | Third-party LaTeX corpora downloaded with `pdf2md datasets install` | **Opt-in, not in version control** | Additional Plan 1 (this doc); future Plan 18 compilation |
| `groundtruth/manifest/external_datasets.json` | Global index of installed external datasets | Generated; git-ignored | Operator/CLI introspection |

The synthetic corpus tests specific LaTeX features in isolation. External
datasets provide complementary coverage — many small isolated examples,
or one realistic multi-file project — but they are **not automatically
canonical approved fixtures**. They are candidates for compilation and
ingestion in a follow-up plan.

---

## Supported datasets

The registry currently ships three entries (see
`src/pdf2md/datasets/registry.py`):

### `tlc3-examples` (alias: `tlc3`)

Many small isolated examples from *The LaTeX Companion 3rd edition*.
Excellent feature-level variety across document classes, floats, fonts,
tables, math, and bibliography.

- **URL:** <https://github.com/FrankMittelbach/tlc3-examples.git>
- **Licence:** LPPL-1.3c (with README-noted exceptions)
- **Kept paths:** `NORMAL/`, `SPECIAL/`, `SUPPORT/`, `README.md`,
  `build.lua`
- **Excluded paths:** `BOOK-PDFS/` (these are reference book PDFs, not
  fixture inputs)
- **Root files:** `NORMAL/**/*.ltx`, `NORMAL/**/*.ltx2`,
  `SPECIAL/**/*.ltx`, `SPECIAL/**/*.ltx2`

### `latex-cookbook` (alias: `cookbook`)

One realistic multi-file project with media, bibliography, glossaries,
TikZ, tables, chemistry, code highlighting, and LuaLaTeX tooling.
Good for end-to-end project compilation stress testing.

- **URL:** <https://github.com/alexpovel/latex-cookbook.git>
- **Licence:** MIT
- **Kept paths:** everything (`.`)
- **Root file:** `cookbook.tex`
- **Recommended engine:** `lualatex`

### `arxiv-curated` (alias: `arxiv`)

**Placeholder slot only. Not yet available for download.** Reserved for
a future curated set of arXiv papers whose LaTeX source is available.
Attempting `pdf2md datasets install arxiv-curated` prints a clear
not-available message and exits non-zero.

## CLI commands

The dataset workflow is exposed via `pdf2md datasets ...`:

### List

```bash
pdf2md datasets list
```

Prints every registered dataset with its id, aliases, licence, and
status (`available` / `not_available` / `installed`).

### Install

```bash
# Download into the default location (groundtruth/external/<name>/upstream/).
pdf2md datasets install tlc3-examples
pdf2md datasets install cookbook                 # alias accepted

# Pick an alternate output root or git ref:
pdf2md datasets install tlc3 --output /tmp/external --ref main

# Plan only, no side effects:
pdf2md datasets install tlc3 --dry-run

# Replace an existing install:
pdf2md datasets install tlc3 --force

# Re-generate dataset.json + manifest.jsonl from an already-cloned tree:
pdf2md datasets install tlc3 --manifest-only

# Install everything that's currently available (skips arxiv-curated):
pdf2md datasets install all
```

### Status

```bash
pdf2md datasets status
```

Reads `groundtruth/manifest/external_datasets.json` and reports
`installed`, `missing` (recorded previously but the directory is gone),
`not_installed`, and `not_available` entries.

## What gets written

Each `pdf2md datasets install <name>` run produces:

```
groundtruth/external/<name>/
├── upstream/                     # the filtered git clone
└── dataset.json                  # dataset-level metadata
└── manifest.jsonl                # one JSON line per root .tex file

groundtruth/manifest/
└── external_datasets.json        # global index across all installed datasets
```

### `dataset.json`

Schema: `pdf2md.ExternalDatasetMeta`. Top-level fields:

```
schema_name, schema_version, id, source_url, ref, resolved_commit,
licence, installed_at (UTC ISO 8601), upstream_path, root_file_count,
compile_status (always "not_run" in this plan)
```

### `manifest.jsonl`

One JSON object per line. Schema:
`pdf2md.ExternalDatasetManifestEntry`. Fields:

```
schema_name, schema_version, id, dataset, root_file, source_type,
has_media, compile_status ("not_run"),
features (e.g. ["bibliography", "figures", "tables"]),
recommended_engine (optional)
```

Manifest generation is **deterministic** — re-running on the same
upstream content produces byte-identical files.

### `external_datasets.json`

Schema: `pdf2md.ExternalDatasetIndex`. The global view across all
installed datasets — useful for tools that want to enumerate the
available corpora without scanning the filesystem.

## Refreshing manifests without re-downloading

If the upstream content is already on disk and you just want to refresh
`dataset.json` + `manifest.jsonl` (e.g. after changing the registry's
glob patterns):

```bash
pdf2md datasets install tlc3-examples --manifest-only
```

The downloader is skipped entirely; only the manifest writers run.

---

## What is explicitly out of scope here

- **Compilation.** This plan does **not** compile any of the
  downloaded LaTeX. `compile_status` stays `not_run` and the
  `--compile`, `--limit`, and `--engine` flags print a "Not implemented
  in Additional Plan 1" message and exit cleanly. Compilation lives in
  a future plan.
- **Automatic acceptance as canonical fixtures.** Downloaded datasets
  are evaluation candidates, not approved fixtures. The Plan 8 ground
  truth tests still use the synthetic corpus.
- **Network in tests.** The unit tests build local git fixtures with
  `git init` / `git commit` in temp directories and never reach the
  network. Real installs of course do hit the upstream repos.

## Module layout

```
src/pdf2md/datasets/
├── __init__.py        # public re-exports
├── registry.py        # DatasetEntry, get_dataset, list_datasets
├── downloader.py      # download_dataset, DownloadResult
├── manifest.py        # generate_dataset_manifest, update_global_index
└── cli.py             # Typer subcommand group `pdf2md datasets ...`
```

The CLI is wired into the main app via
`app.add_typer(datasets_app, name="datasets")` in
`src/pdf2md/cli/main.py`.
