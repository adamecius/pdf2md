## 1. Purpose

The existing ground-truth corpus has 57 synthetic fixtures generated by
the project itself. They test specific LaTeX features in isolation with
controlled structure. External datasets like TLC3 provide 1,446 real-world
examples covering a much wider range of LaTeX features (fonts, verbatim,
advanced tables, bibliography styles, math, graphics, multilingual text).

But the pipeline only reads ground truth from:

```
groundtruth/corpus/latex/<doc_id>/<doc_id>.tex   + meta.toml + .docling.json
```

External datasets land in:

```
groundtruth/external/tlc3-examples/upstream/NORMAL/*.ltx
```

Nothing connects them. This plan creates that connection.

After this plan:

- `pdf2md datasets ingest tlc3` takes TLC3's 1,446 `.ltx` files, creates
  corpus entries under `groundtruth/corpus/latex/tlc3-<id>/`, generates
  `meta.toml` and `.docling.json` for each.
- A triage report classifies each entry as `full`, `partial`, or
  `unsupported` based on parser warnings.
- The ingested entries are immediately visible to `local/groundtruth.py`,
  `tools/calibrate_priors.py`, and the backend evaluation pipeline.
- The existing 57 corpus fixtures are untouched.

## 4. Scope, constraints, and dependencies

In scope:

1. Ingestion script that positions external `.ltx` / `.tex` as corpus entries.
2. Automatic `meta.toml` generation from TLC3 header comments.
3. Symlink or copy of TLC3 `support/` files so `\documentclass{tlc3exa}`
   resolves.
4. Invocation of `tools/latex_to_docling.py` per entry for `.docling.json`
   generation.
5. Triage report classifying ingestion quality per entry.
6. CLI subcommand `pdf2md datasets ingest <dataset>`.
7. Unit tests using synthetic fixtures (no network, no real TLC3).

Out of scope:

1. LaTeX compilation to PDF (future plan).
2. Backend execution on ingested entries.
3. Modifying the LaTeX parser to handle more commands.
4. Modifying existing corpus fixtures.
5. Ingesting latex-cookbook (single multi-file project requiring lualatex;
   the parser cannot handle its full complexity).

Hard constraints:

1. The agent must not modify `tools/latex_to_docling.py`.
2. The agent must not modify anything under `groundtruth/corpus/latex/`
   that already exists.
3. Newly created corpus entries must follow the exact same convention as
   existing fixtures: `<doc_id>/<doc_id>.tex` + `meta.toml` +
   `<doc_id>.docling.json` + `<doc_id>.docling_groundtruth_meta.json`.
4. The `support/` dependency must be resolved without copying 15+ files
   per entry — use a shared symlink or set TEXINPUTS.

## 6. Agent tasks

### Task A1 — Meta.toml generator from TLC3 headers

Title:
Parse TLC3 header comments to generate meta.toml

Goal:
Implement `src/pdf2md/datasets/meta_generator.py` that extracts metadata
from TLC3 `.ltx` file headers and produces `meta.toml`.

Files allowed:

```text
src/pdf2md/datasets/meta_generator.py
tests/test_meta_generator.py
```

Implementation requirements:

1. Parse TLC3 header comments. Every `.ltx` file has:

   ```text
   %% Example 1-3-1 on page I-16 in "Typographic conventions".
   ```

   Extract: example_id (`1-3-1`), page (`I-16`), section_title
   (`Typographic conventions`).

   Regex:

   ```python
   re.compile(r'Example\s+([\d-]+)\s+on page\s+(\S+)\s+in\s+"([^"]+)"')
   ```

2. Parse `\documentclass{...}` from the file body. Extract the class name
   (e.g., `tlc3exa`, `article`).

3. Detect features by scanning for known environments and commands:
   - `\begin{equation}` → `equations`
   - `\begin{figure}` → `figures`
   - `\begin{table}` → `tables`
   - `\begin{itemize}` / `\begin{enumerate}` → `lists`
   - `\footnote{` → `footnotes`
   - `\ref{` → `references`
   - `\cite{` / `\begin{thebibliography}` → `bibliography`
   - `\begin{verbatim}` / `\verb` → `verbatim`
   - `$...$` / `\begin{align}` → `math`

4. Generate `meta.toml` content:

   ```toml
   source_path = "groundtruth/corpus/latex/tlc3-1-3-1/tlc3-1-3-1.tex"
   document_id = "tlc3-1-3-1"
   documentclass = "tlc3exa"
   origin = "tlc3-examples"
   tlc3_example_id = "1-3-1"
   tlc3_page = "I-16"
   tlc3_section = "Typographic conventions"
   expected_features = ["references"]
   expected_counts = {}
   notes = "TLC3 Example 1-3-1: Typographic conventions (auto-generated)"
   ```

5. Provide `generate_meta_toml(ltx_path: Path, corpus_doc_id: str) -> str`
   returning the TOML string.

Automated tests required:

```bash
conda run -n pdf2md pytest tests/test_meta_generator.py -q
```

Tests must cover:
- Standard TLC3 header parsing
- Missing header (graceful fallback)
- Feature detection for equations, figures, tables, lists
- documentclass extraction

Human verification required:
no

### Task A2 — Ingestion script

Title:
Implement external dataset → corpus ingestion

Goal:
Implement `src/pdf2md/datasets/ingest.py` that takes an external dataset
directory and creates corpus entries.

Files allowed:

```text
src/pdf2md/datasets/ingest.py
tests/test_dataset_ingest.py
tests/data/ingest_fixtures/.gitkeep
```

Implementation requirements:

1. Implement `ingest_tlc3(external_dir: Path, corpus_root: Path, **opts) -> IngestReport`:

   For each `.ltx` / `.ltx2` in `external_dir/upstream/NORMAL/` and
   `external_dir/upstream/SPECIAL/`:

   a. Compute `corpus_doc_id = f"tlc3-{stem}"` (e.g., `tlc3-1-3-1`).

   b. Create `corpus_root/tlc3-{stem}/`.

   c. Copy the `.ltx` file as `corpus_root/tlc3-{stem}/tlc3-{stem}.tex`.

   d. Create a relative symlink `support` pointing to the external
      dataset's `support/` directory:

      ```python
      (corpus_entry / "support").symlink_to(
          os.path.relpath(external_dir / "upstream" / "support", corpus_entry)
      )
      ```

      This makes `\documentclass{tlc3exa}` resolve via the symlinked
      `support/tlc3exa.cls`.

   e. Generate `meta.toml` using `meta_generator.generate_meta_toml()`.

   f. Call `latex_to_docling.build_docling_from_tex()` to produce the
      `.docling.json` and `.docling_groundtruth_meta.json`. Import the
      function directly — do not spawn a subprocess.

   g. Catch exceptions from the parser. If it fails, write a minimal
      `.docling.json` with `{"schema_name": "DoclingDocument", ...}`
      and record the entry as `unsupported` in the triage report.

   h. Classify the entry based on the `warnings` list from the
      groundtruth meta:
      - `full`: zero warnings
      - `partial`: has warnings but produced some structure
      - `unsupported`: parser raised an exception

2. Options:
   - `force: bool = False` — overwrite existing corpus entries
   - `limit: int | None = None` — process only first N entries
   - `dry_run: bool = False` — report what would happen
   - `prefix_filter: str | None = None` — only ingest entries matching
     prefix (e.g., `"1-"` for chapter 1 examples)

3. If the corpus entry already exists and `force` is not set, skip it.

4. Return an `IngestReport` dataclass:

   ```python
   @dataclass
   class IngestReport:
       dataset_id: str
       total_sources: int
       ingested: int
       skipped: int
       full_groundtruth: int
       partial_groundtruth: int
       unsupported: int
       errors: list[str]
       entries: list[IngestEntry]
   ```

5. Write `external_dir/ingest_report.json` with the report.

Automated tests required:

```bash
conda run -n pdf2md pytest tests/test_dataset_ingest.py -q
```

Tests must use synthetic fixtures (a tiny fake TLC3 layout with 2–3
`.ltx` files and a minimal `support/` directory with a dummy `.cls`).
Tests must cover:
- Successful ingestion of a simple .ltx
- Corpus entry has correct naming convention
- Symlink to support/ is created
- meta.toml is generated
- Ingestion with force overwrites
- Ingestion without force skips existing
- dry_run produces no files
- prefix_filter limits ingestion
- Parser failure is classified as unsupported

Human verification required:
no

## 11. Design notes

### Why symlink support/ instead of copy?

TLC3's `support/` directory contains 20+ files (class files, images,
bibliography databases). Copying them into each of the 1,446 corpus
entries would create ~29,000 duplicate files. A single relative symlink
per entry solves the dependency with zero duplication:

```
groundtruth/corpus/latex/tlc3-1-3-1/support
  → ../../../external/tlc3-examples/upstream/support
```

This requires that the external dataset remains downloaded. If it is
deleted, the symlinks break and the corpus entries become non-functional.
This is acceptable because the external dataset is a prerequisite.

On Windows (without developer mode symlinks), fall back to copying
`support/` once into a shared location and symlinking to that, or
document the limitation.

### Why not ingest latex-cookbook?

`latex-cookbook` is a single multi-file project using lualatex with
glossaries, minted (Python/Pygments), polyglossia, TikZ, gnuplot,
CSV plotting, and chemistry packages. The existing parser handles
none of these. Ingesting it would produce an empty or nearly-empty
`.docling.json`, which is not useful.

A future plan could add a lualatex-aware parser or use a different
ground-truth extraction strategy (e.g., LaTeXML → XML → DoclingDocument).

### Expected triage distribution

Based on the parser's known command coverage (`section`, `subsection`,
`equation`, `figure`, `table`, `itemize`, `enumerate`, `footnote`,
`caption`, `label`, `ref`, `cite`) vs. TLC3's content:

- Chapters 1–3 (general LaTeX, document structure): mostly `full`
- Chapters 4–5 (verbatim, tabular): mostly `partial` (unknown commands)
- Chapters 6–9 (floats, fonts, math): mixed `partial` / `unsupported`
- Chapters 10–13 (fonts, graphics, bibliography): mostly `partial`
- Chapters 14–17 (internals, engines): mostly `unsupported`

The exact distribution will be known after Checkpoint H2.

### Relationship to calibration

After ingestion, the corpus entries have `.docling.json` ground truth
but NOT `truth.json` (the calibration format). To use them for
calibration:

1. Run backends on the compiled PDFs (requires Plan 18 + compilation).
2. Generate `truth.json` from `.docling.json` (requires a converter
   from DoclingDocument → CalibrationTruthDocument).

This is out of scope for this plan but is the natural next step.
