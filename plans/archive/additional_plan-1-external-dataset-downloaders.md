## 1. Purpose

This plan adds an opt-in CLI workflow that allows users to download, position,
and manifest selected external LaTeX source corpora for later local compilation
and backend evaluation.

The existing ground-truth corpus under `groundtruth/corpus/latex/` consists of
synthetic fixtures generated by `generate_latex_docling_groundtruth.py`. Those
fixtures test specific LaTeX features in isolation. External datasets provide
complementary coverage:

- **tlc3-examples**: many small isolated examples from The LaTeX Companion 3rd
  edition — good for feature-level variety across document classes, floats,
  fonts, tables, math and bibliography.
- **latex-cookbook**: one realistic multi-file project with media, bibliography,
  glossaries, TikZ, tables, chemistry, code highlighting and LuaLaTeX tooling —
  good for end-to-end project compilation stress testing.
- **arxiv-curated** (registry entry only, not downloaded in this plan): a future
  slot for a small curated set of arXiv papers with source LaTeX available,
  providing the strongest test of real-world PDF extraction quality.

Downloaded datasets are positioned under `groundtruth/external/` and remain
strictly separated from the canonical generated corpus. They are candidates for
compilation and ingestion in Plan 18, not automatically approved fixtures.

## 4. Scope, constraints, and dependencies

In scope:

1. Dataset registry module defining supported external datasets.
2. Git-based downloader with atomic positioning and exclusion rules.
3. Per-dataset manifest generation (dataset.json + manifest.jsonl).
4. Global external dataset index (groundtruth/manifest/external_datasets.json).
5. Typer CLI subcommand group `datasets` integrated into the existing CLI.
6. Dry-run mode for all operations.
7. Unit tests that work without network access.
8. Documentation under docs/datasets.md.

Out of scope:

1. LaTeX compilation pipeline.
2. PDF generation from downloaded sources.
3. Backend execution on downloaded datasets.
4. IR extraction or benchmark scoring.
5. Ground-truth promotion or human approval workflow.
6. Uploading or vendoring datasets into the repository.
7. Downloading arXiv papers (registry entry only in this plan).

Hard constraints:

1. The agent must not modify files outside the whitelist.
2. The agent must not mark this plan as human_verified or finished.
3. The agent may only mark agent_in_progress, agent_complete, human_verification_required, blocked, or superseded.
4. Human verification is required before merge to main.
5. Datasets must not be downloaded during normal package installation.
6. Datasets must only be downloaded when the user explicitly requests them through a CLI command.
7. No dataset is marked as validated unless compilation has actually been run (in Plan 18).
8. The `git` command must be available on the system. If missing, fail clearly.

### Task A2 — Git downloader with atomic positioning

Title:
Implement safe git downloader with keep/exclude rules

Goal:
Implement `src/pdf2md/datasets/downloader.py` that clones a dataset, applies
keep/exclude filtering, and atomically places the result under
`groundtruth/external/<dataset>/upstream/`.

Files allowed:

```text
src/pdf2md/datasets/downloader.py
tests/test_dataset_downloader.py
tests/data/fake_repo/.gitkeep
```

Implementation requirements:

1. Clone the dataset URL into a temporary directory inside the output parent
   using `subprocess.run(["git", "clone", ...])`.

2. Support `--ref` for branch or commit checkout. Use `--depth 1` for branch
   refs. For exact commit refs, clone without depth then checkout.

3. After cloning, apply the dataset's keep_paths and exclude_paths:
   - For tlc3-examples: copy only NORMAL/, SPECIAL/, SUPPORT/, README.md,
     build.lua into upstream/. Delete BOOK-PDFS/ if present. Preserve media
     PDFs inside SUPPORT/ (these are figure assets, not book PDFs).
   - For latex-cookbook: move the full clone into upstream/.

4. Atomically rename the temporary directory to the final path. If the final
   path already exists and `--force` is not set, raise an error. If `--force`
   is set, remove the existing directory first.

5. Clean up temporary directories on failure where practical.

6. Fail clearly with a useful message if `git` is not installed (check with
   `shutil.which("git")`).

7. Record the resolved commit SHA via `git rev-parse HEAD` after checkout.

8. Return a result dataclass with: dataset_id, output_path, resolved_commit,
   ref_used, success, error_message.

Automated tests required:

```bash
conda run -n pdf2md pytest tests/test_dataset_downloader.py -q
```

Tests must use local temporary git repositories (created with `git init` +
`git commit` in a temp dir), not real network clones. Tests must cover:
- successful clone and positioning
- keep/exclude filtering (BOOK-PDFS excluded for tlc3-like fixture)
- --force replaces existing
- without --force, existing directory raises error
- missing git binary raises clear error

Expected output:
Module importable as `from pdf2md.datasets.downloader import download_dataset`.

Completion evidence:
Files changed, tests run, exit codes.

## 8. Test matrix and failure classification

Agent automated test matrix:

```bash
conda run -n pdf2md pytest tests/test_dataset_registry.py -q
conda run -n pdf2md pytest tests/test_dataset_downloader.py -q
conda run -n pdf2md pytest tests/test_dataset_manifest.py -q
conda run -n pdf2md pytest tests/test_dataset_cli.py -q
```

Human verification test matrix:

```text
pdf2md datasets list
pdf2md datasets install tlc3 --dry-run
pdf2md datasets install tlc3 --output /tmp/pdf2md_test_datasets
pdf2md datasets status
```

Network tests:
Tests that require network access must be gated behind the environment variable
`PDF2MD_ENABLE_NETWORK_TESTS=1`. Normal `pytest` runs must pass without network.

Failure classes:

repository_defect:
The implementation is wrong, a test fails due to logic, an output schema is
invalid, or a CLI signature is broken.

environment_missing:
git is not installed, network is unavailable for network tests, or the conda
environment is not configured.

test_expectation_wrong:
The test or checkpoint expectation is inconsistent with the plan or repository
contract.

human_procedure_error:
The human ran the wrong command, used the wrong environment, or inspected the
wrong file.

upstream_dependency_issue:
The external GitHub repository (tlc3-examples or latex-cookbook) changed structure,
was deleted, or is temporarily unavailable.

permission_or_filesystem_error:
The command cannot write, read, or access required paths.

timeout:
git clone did not finish within a reasonable time.

Failure handling:

If failure_class is repository_defect:
The agent must fix the implementation or report a blocker.

If failure_class is environment_missing:
The human or environment owner must fix the environment, or report git/network
availability.

If failure_class is upstream_dependency_issue:
Document the issue. If the external repo changed structure, the registry entry
must be updated. If temporarily unavailable, retry later.

### Relationship to existing ground truth

The existing `groundtruth/corpus/latex/` fixtures are synthetic documents
generated by `generate_latex_docling_groundtruth.py` with known structure
recorded in `meta.toml` and `.docling.json` files. They test specific LaTeX
features in isolation.

External datasets under `groundtruth/external/` are third-party corpora
downloaded as-is. They do not have pre-generated Docling ground truth. Plan 18
will handle compilation (LaTeX → PDF) and Plan 19+ may address ground-truth
extraction from the LaTeX source.

### Why arXiv as a future third source

TLC3 provides many small examples. latex-cookbook provides one realistic project.
Neither fully exercises the extraction pipeline on real academic documents with
complex layouts, multi-column text, embedded figures, tables spanning pages,
and bibliography formatting.

arXiv papers with available source LaTeX provide the strongest real-world
coverage. The source LaTeX gives structural ground truth (sections, equations,
figures, tables, references) and the compiled PDF is the extraction target.
A curated set of 20–50 papers covering diverse document classes (article,
revtex, llncs, aaai, neurips) would substantially improve benchmark coverage.

This is deferred because:
- arXiv source download requires different tooling (S3 bulk access or per-paper API)
- Ground truth extraction from arbitrary LaTeX is harder than from controlled fixtures
- The download/position/manifest infrastructure must be stable first

### Suggested Plan 18 scope

Plan 18 should implement compilation and evaluation:

1. Compile TLC3 candidates with pdflatex.
2. Compile latex-cookbook with lualatex (requires fuller TeX installation).
3. Store generated PDFs alongside source.
4. Record compilation logs and classify failures.
5. Produce a successful-subset manifest.
6. Optionally run backend extraction on compiled PDFs.
7. Optionally promote selected compiled examples into the canonical ground-truth
   corpus after human approval.
