# pdf2md — cross-reference examples (analysis snapshot)

This branch contains **only** the cross-reference example data, isolated
from the rest of the pdf2md codebase so it can be analysed on its own.
There is no source code here — just the generated semantic-graph
fixtures for three documents.

## What's here

```
data/
├── manifest.json          registry: examples × semantic backends × OCR backends
├── example01/             1410.8140.pdf  — physics article, 10 pages
├── example02/             math/CS article, 17 pages
└── example3/              book_1.pdf     — 791-page book (book-class)
```

Each example directory holds:

| file pattern | what it is |
|---|---|
| `<semantic>.json` | raw `CrossReferenceGraph` from one semantic backend (`regex` / `grobid` / `vlm_v4` / `consensus`) — markers + entities + edges |
| `entities_<ocr>.json` | `EntityProposalDocument` from one OCR backend (`deepseek` / `mineru` / `paddleocr` / `consensus`) — the candidate side |
| `<semantic>__resolved_with__<ocr>.json` | D3 graph payload: markers resolved against that OCR's candidates. Edges carry `resolved`, `marker_type`, `label`, `edge_kind` |
| `consensus.json` | best-of-confidence merge of the three semantic backends |
| `entities_consensus.json` | entity-level merge of the three OCR backends |

## Graph payload schema (`*__resolved_with__*.json`)

```json
{
  "schema_version": "1.1.0",
  "document_id": "example3/grobid+deepseek",
  "nodes": [
    {"id": "...", "type": "document|page|<section>|<marker_type>|unresolved",
     "label": "...", "page_no": 7, "parent_id": "..."}
  ],
  "edges": [
    {"source": "...", "target": "...", "edge_kind": "cross_reference|contains|page_sequence",
     "marker_type": "bibliography|equation|figure|...", "label": "[15]", "resolved": true}
  ],
  "metadata": {
    "total_markers": 3937, "resolved_count": 3246, "unresolved_count": 691,
    "has_hierarchy": true,
    "document_class": "book", "document_class_confidence": 0.95,
    "document_class_features": {"page_count": 791, "chapter_count": 16, ...}
  }
}
```

An edge whose `target` is `"_unresolved"` is an unresolved marker.

## Useful analysis entry points

* **Unresolved markers**: filter edges where `edge_kind == "cross_reference"` and `resolved == false`; group by `marker_type`; inspect `label`.
* **Document class**: `entities_<ocr>.json → metadata.document_class` (+ `_features`).
* **Per-backend resolution rate**: `metadata.resolved_count / metadata.total_markers` in each `*__resolved_with__*.json`.
* **Hierarchy**: `contains` edges encode Document → Page/Section → Entity; `page_sequence` edges chain adjacent pages.

## Provenance

Generated by the pdf2md pipeline (semantic backends: regex / GROBID /
DeepSeek-VL2; OCR backends: DeepSeek-OCR / MinERU / PaddleOCR). This
snapshot reflects the resolver state as of the `marker-resolver-fixes`
work (equation letter-prefixes, GROBID bib-noise drops, chapter→section
downcast, footnote comma-split, numbering-aware fuzzy matching).
